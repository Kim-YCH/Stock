# 線圖技術指標即時補齊與背景自癒設計

## 目標

當使用者開啟個股線圖，而 `Indicators` 尚未包含 KD、布林 %B、ATR %、ADX14、20 日高低、EMA20、VWAP20、OBV、MFI14、CCI20、SuperTrend 或 Donchian 20 時，仍能在同一次分析請求中取得完整線圖與指標；不得因補寫整張試算表而明顯拖慢畫面。

## 根因

- 後端已具備所有缺漏指標的公式，問題不是公式不存在。
- `getAnalysis_` 發現分析快取無效後，只會再次從現有 `Indicators` 建立快取，沒有啟用既有的單檔補算選項，因此會反覆讀到同一批空欄位。
- 每日指標工作判斷單檔是否完成時只比對日期；日期正確但欄位不完整的資料，可能被視為已完成。
- 同步呼叫既有 `updateAnalysisFromPrices_([symbol])` 會掃描並覆寫大型 `Indicators` 表，不適合放在線圖首屏的阻塞路徑。

## 採用方案

採用「請求內記憶體補算＋背景持久化修復」：

1. 分析請求照常一次讀取該股票近期 Prices、Indicators 與 Signals。
2. 若最新 Indicators 不完整且至少有 60 筆有效收盤價，直接使用已讀取的近期 Prices 在 Apps Script 記憶體中計算完整指標列。
3. 以記憶體計算結果補齊回應中的 `latest` 與 120 日線圖資料，不在請求內改寫 Indicators。
4. 將完整分析結果寫入既有六小時快取，後續點擊直接命中快取。
5. 同時將股票代碼排入去重的背景修復佇列；背景工作一次處理少量股票，呼叫既有單檔持久化流程，完成後清除該股票分析快取。
6. 每日工作判斷完成條件改為「日期正確且必要技術欄位完整」，避免部分資料永久被跳過。

不採用線圖請求內同步寫回 Indicators，因為大型 Sheet 的掃描、列定位與寫入會讓首屏等待時間不穩定。也不採用每次都只做暫時計算而永不修復資料庫，避免快取過期後重複補算。

## 元件與資料流

### 指標完整性定義

建立單一必要欄位清單，供以下位置共用：

- 分析快取有效性檢查
- `technicalStatus` 缺漏訊息
- 每日指標工作完成判斷
- 是否需要記憶體補算及背景修復

必要欄位涵蓋畫面顯示與線圖會使用的全部技術值，不再只檢查部分核心欄位。

### 純記憶體計算

把現有 `updateAnalysisFromPrices_` 中「由單一股票 Prices 產生指標列」的純計算部分抽成可重用函式。它只接收標準化價格資料並回傳指標列與訊號列，不存取 Sheet、不取得鎖。

既有批次／單檔持久化流程改用同一函式，避免線圖補算與每日批次出現公式差異。分析請求僅使用回傳的指標列合併畫面資料。

### 背景修復佇列

- 以 Script Properties 保存待修復股票集合，加入時去重。
- 僅保留合法台股代碼，並設定合理的最大佇列長度。
- 使用單一 one-shot trigger；若 trigger 已存在，不重複建立。
- 每次執行處理少量股票並遵守時間預算；未完成者保留至下一輪。
- 單檔失敗記錄有限次數，避免無限重試阻塞其他股票。
- 成功後清除 `analysis:<symbol>` 的記憶體與 DashboardCache，使下次讀取持久化結果。

## 使用者體驗

- 線圖第一次打開即可取得暫時計算完成的數據，不顯示「部分技術指標尚未計算」。
- 不新增阻塞式等待畫面，也不要求使用者手動重算。
- 若歷史價格不足 60 筆，保留缺漏提示，因為此時部分指標無法可靠計算。
- 背景寫回失敗不影響當次線圖；快取期間仍使用記憶體計算結果。

## 錯誤處理

- 記憶體補算失敗時，回傳原本可用資料及明確缺漏狀態，不讓整個分析 API 失敗。
- 背景 trigger 建立失敗時，不影響分析回應。
- 背景修復每檔隔離錯誤，單一股票失敗不終止整批。
- 佇列狀態與錯誤文字限制大小，避免超過 Script Properties 配額。

## 效能界線

- 分析請求不新增外部網路請求。
- 分析請求不寫入 Indicators、Signals 或 IndicatorsLatest。
- 純計算重用該請求已讀取的單檔價格資料，時間複雜度為 O(N)，N 最多為單檔近期歷史筆數。
- 持久化寫入只在背景執行，且一次只處理少量股票。

## 測試

1. 不完整 Indicators 加上足夠 Prices 時，分析回應會補齊全部必要欄位與線圖序列。
2. 已完整資料不觸發記憶體補算或背景排程。
3. 價格不足時不偽造無法計算的指標，仍回報缺漏。
4. 同一股票重複請求只在修復佇列出現一次。
5. 每日完成判斷同時驗證日期與欄位完整性。
6. 背景成功後移除佇列項目並清除分析快取；失敗時可重試且不影響其他股票。
7. 原有後端及前端測試全部通過。

## 範圍

本次修改集中於分析資料產生、指標完整性判斷、背景單檔修復與相關測試。線圖版面、選股策略、其他頁面及交易功能不變。
