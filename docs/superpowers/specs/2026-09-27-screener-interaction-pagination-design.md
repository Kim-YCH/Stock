# 選股互動與快速分頁設計

## 目標

將選股策略頁面升級為 v11.24，改善三個使用體驗問題：防止選股任務重複送出、簡化只有 `in` 運算子的條件介面，以及讓結果上一頁／下一頁在第一頁載入後盡量於 1 秒內顯示。其他頁面與既有選股規則不變。

## 使用者介面

### 選股執行狀態

- 使用者按下「開始選股」後，前端立即進入執行中狀態。
- 執行中按鈕停用，文字改為「選股中」，並在文字旁顯示小型旋轉動畫。
- 按鈕加上 `aria-busy="true"`，讓輔助工具能辨識載入狀態。
- 執行中再次觸發點擊事件時，前端直接忽略，不呼叫第二次 `startScreener`。
- 執行中狀態涵蓋初始請求及後續輪詢；只有任務進入 `COMPLETED` 或 `FAILED`，或初始請求確定失敗時，按鈕才恢復為「開始選股」。
- 重新進入選股頁時，如果記憶體中的任務仍未結束，按鈕維持「選股中」。

### `in` 條件

- 當條件定義的 `ops` 只有一個值且為 `in` 時，不渲染運算子下拉選單。
- 使用者直接勾選該條件的列舉值；既有序列化格式仍為 `{ field, op: "in", value: [...] }`，後端 API 不需改變條件格式。
- 具有多個運算子的條件仍保留原有下拉選單。

### 分頁載入

- 換頁期間保留目前表格內容，避免空白或跳動。
- 分頁容器進入忙碌狀態，上一頁與下一頁暫時停用並顯示小型載入提示。
- 新頁面成功載入後一次替換表格與分頁狀態；失敗時保留原頁並顯示錯誤。
- 快速連續切頁時只接受最新請求的回應，較舊回應不可覆蓋目前頁面。

## 前端狀態與資料流程

`screenerState` 增加兩類狀態：

- 選股執行狀態：以現有 `job.status` 為主要依據，搭配初始請求中的旗標，統一由一個按鈕同步函式控制文字、停用與動畫。
- 分頁狀態：記錄目前分頁請求序號、載入中狀態，以及以 `jobId + page + sortField + sortDirection` 為鍵的頁面 Promise／結果快取。

資料流程：

1. 使用者按下開始選股，前端先鎖定按鈕，再序列化條件並送出一次請求。
2. 初始回應建立 `job`，前端依任務狀態保持鎖定或恢復按鈕。
3. 輪詢每次更新 `job` 後同步按鈕狀態；終止狀態停止輪詢。
4. 結果頁載入後，前端背景預抓有效的上一頁與下一頁。
5. 使用者切頁時優先使用前端已預抓的結果；未命中時呼叫後端。

## 後端結果快取

目前每次 `screenerResults` 請求都會重新讀取完整 `ScreenerJobs` 與 `ScreenerResults` 工作表、篩選該任務、解析所有 JSON，並重新排序。這是換頁約需 5 秒的主要原因。

v11.24 採用每任務結果快取：

- 快取內容是已解析的該任務結果列，而不是全域 `ScreenerResults`。
- 快取身分包含擁有者、`jobId`、結果修訂值（使用任務的 `matchCount`／更新狀態）及排序欄位與方向。
- 快取命中時可直接驗證擁有者並切出指定的 10 筆，不重新掃描工作表。
- 快取未命中時沿用目前的工作表讀取與權限驗證，再建立快取。
- 結果數量改變時使用新的修訂快取鍵，舊快取自然依短期 TTL 淘汰，避免讀到未完成批次的舊資料。
- 快取沿用既有 `getCachedJson_`／`putCachedJson_` 分塊機制，避免 Apps Script 單一快取項目的大小限制。
- 快取只是加速層；遺失或寫入失敗時仍回退到工作表，正確性不依賴快取。

第一頁的既有讀取會暖起相同任務與排序的快取；前端隨後預抓相鄰頁，使一般上一頁／下一頁操作目標在 1 秒內完成。

## 錯誤處理

- 初始選股請求失敗時解除按鈕、移除動畫並顯示既有錯誤訊息。
- 輪詢暫時失敗但任務仍非終止狀態時保持「選股中」，並沿用既有重試機制。
- 分頁請求失敗時不清空目前結果，也不改變目前頁碼。
- 預抓失敗不顯示干擾性錯誤；使用者實際切頁時仍可重新請求。
- 快取資料若無法解析、版本不符或擁有者不符，一律視為未命中並回退工作表。

## 測試

- 前端測試：連續點擊只呼叫一次 `startScreener`。
- 前端測試：執行期間按鈕停用、文字為「選股中」、具有忙碌狀態與動畫；完成、失敗及初始錯誤後恢復。
- 前端測試：只有 `in` 的列舉條件沒有運算子下拉選單，但複選框與序列化資料維持正確。
- 前端測試：結果載入後預抓相鄰頁；快取命中不重複呼叫 API。
- 前端測試：較舊的分頁回應不覆蓋較新的頁面。
- 後端測試：相同任務、修訂與排序的第二次分頁讀取命中快取，不再次掃描結果工作表。
- 後端測試：不同擁有者、不同任務、不同結果修訂及不同排序不共用快取。
- 後端測試：快取未命中或失效時仍能從工作表取得正確的 10 筆結果。
- 執行完整語法檢查與全部既有測試，確認其他頁面沒有回歸。
